# Plan 07-04: CI Pipeline Sync & Integration Tests

## Objective

Ensure the CI pipeline works with the new frontend, and add integration tests that verify the key API integration flows. After this plan, every push/PR will validate that the frontend builds, lints, and its API integration tests pass.

## Context

The existing `ci.yml` frontend-build job already has the right structure but was written for the old frontend. The new frontend must satisfy the same contract. This plan also adds MSW-based integration tests that prove the API client layer (Plans 01-03) works correctly without requiring a real backend.

**Note:** MSW v2 is the current standard and uses `http` from `msw`. Install if needed:
```bash
npm install --save-dev msw
```

## Implementation

### Task 1: Audit and Update `.github/workflows/ci.yml`

Read the existing `ci.yml`. The frontend-build job currently does:
1. `npm ci --legacy-peer-deps` (with `cache-dependency-path: frontend/package-lock.json`)
2. `npx vitest run`
3. `npm run lint`
4. `NEXT_PUBLIC_BACKEND_URL=http://localhost:8000 npm run build`

**Do NOT change the backend-test job** — it is correct and complete.

Update the frontend-build job ONLY if the new frontend:
- Uses a different lockfile (e.g., `bun.lock` → change cache-dependency-path and install command)
- Has different script names in `package.json` (e.g., `test` instead of `vitest run`)
- Requires additional env vars for build

If the new frontend uses npm with `package-lock.json`, the CI job may not need changes.
If the new frontend uses bun, update to:
```yaml
- name: Install Dependencies
  run: |
    cd frontend
    bun install
- name: Run Tests  
  run: |
    cd frontend
    bun run test
- name: Lint
  run: |
    cd frontend
    bun run lint
- name: Build
  run: |
    cd frontend
    NEXT_PUBLIC_BACKEND_URL=http://localhost:8000 bun run build
```

Also update the `cache` and `cache-dependency-path` fields accordingly.

**Add a gatekeeper job** if not already present:
```yaml
gatekeeper:
  needs: [backend-test, frontend-build]
  runs-on: ubuntu-latest
  steps:
    - name: All checks passed
      run: echo "All CI checks passed"
```

### Task 3: Update `frontend/src/test/setup.ts`

Configure MSW server for Vitest. This file is referenced from `vitest.config.ts` as `setupFiles`:

```ts
import { beforeAll, afterAll, afterEach } from 'vitest';
import { setupServer } from 'msw/node';
import { handlers } from './handlers';

export const server = setupServer(...handlers);

beforeAll(() => server.listen({ onUnhandledRequest: 'warn' }));
afterEach(() => server.resetHandlers());
afterAll(() => server.close());
```

### Task 4: Create `frontend/src/lib/__tests__/api.test.ts`

Unit tests for `apiFetch`:

```ts
import { describe, it, expect, beforeEach, afterEach } from 'vitest';
import { apiFetch, ApiError } from '../api';

describe('apiFetch', () => {
  beforeEach(() => localStorage.clear());
  afterEach(() => localStorage.clear());

  it('calls health endpoint and returns JSON', async () => {
    const result = await apiFetch<{ ok: boolean }>('/api/health');
    expect(result.ok).toBe(true);
  });

  it('throws ApiError on 401 response', async () => {
    await expect(
      apiFetch('/api/auth/token', { method: 'POST', body: JSON.stringify({ role: 'admin', secret: 'wrong' }) })
    ).rejects.toThrow(ApiError);
  });

  it('attaches Authorization header when token in localStorage', async () => {
    localStorage.setItem('nagraksha_token', 'mock-jwt-token');
    // Mock handler captures the request — we verify via successful response
    const result = await apiFetch<{ ok: boolean }>('/api/health');
    expect(result.ok).toBe(true);
  });
});
```

### Task 5: Create `frontend/src/lib/__tests__/nagraksha.test.ts`

Integration tests for the typed API functions:

```ts
import { describe, it, expect } from 'vitest';
import { getHealth, triggerSos, getHospitals, getAuthToken, getStats } from '../nagraksha';

describe('NagRaksha API Integration', () => {
  it('getHealth returns ok:true', async () => {
    const result = await getHealth();
    expect(result.ok).toBe(true);
    expect(result.service).toBe('nagraksha-backend');
  });

  it('triggerSos returns incidentId and 3 lanes', async () => {
    const result = await triggerSos({ lat: 12.8003, lng: 77.5954 });
    expect(result.incidentId).toBe('mock-incident-id-123');
    expect(result.lanes).toHaveLength(3);
    expect(result.lanes[0].outcome).toBe('PENDING');
  });

  it('getHospitals returns ranked hospital list', async () => {
    const result = await getHospitals(12.8003, 77.5954);
    expect(result.hospitals).toHaveLength(1);
    expect(result.hospitals[0].stock?.status).toBe('IN_STOCK');
  });

  it('getAuthToken returns JWT for valid victim credentials', async () => {
    const result = await getAuthToken('victim', 'victim-demo');
    expect(result.token).toBe('mock-jwt-token');
    expect(result.role).toBe('victim');
  });

  it('getStats returns totals with expected shape', async () => {
    const result = await getStats();
    expect(result.totals.incidents).toBeGreaterThanOrEqual(0);
    expect(result.incidentTrend14d).toHaveLength(14);
    expect(result.parallelDispatchLanes).toBe(3);
  });

  it('getAuthToken throws ApiError for invalid credentials', async () => {
    const { ApiError } = await import('../api');
    await expect(getAuthToken('admin', 'wrong')).rejects.toThrow(ApiError);
  });
});
```
