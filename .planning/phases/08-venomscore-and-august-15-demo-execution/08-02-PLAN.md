## Contract Pin (Review HIGH — one canonical naming, no dual schemas)

The following contract is canonical across Pydantic, SQLite rows, domain dicts, WS payloads, and TypeScript (08-03). Where 08-PATTERNS.md or 08-RESEARCH.md diverge, this table wins:

| Layer | Naming |
|---|---|
| HTTP request body (JSON) | snake_case: `right_aperture`, `left_aperture`, `avg_aperture`, `baseline_aperture`, `percent_change`, `ptosis_detected`, `severity`, `asymmetric`, `minutes_since_bite` |
| DB columns (PtosisReading) | camelCase: `rightAperture`, `leftAperture`, `avgAperture`, `baselineAperture`, `percentChange`, `ptosisDetected`, `severity`, `asymmetric`, `minutesSinceBite`, `createdAt` (matches reference schema + wound.py camelCase precedent) |
| Domain dicts in/out | accept camelCase keys with snake_case fallback (`percentChange` OR `percent_change`, `ptosisDetected` OR `ptosis_detected`); emit camelCase |
| Response + WS payload | camelCase: `{"id": ..., "venomScore": {...}}`; `{"venomScore": {...}}`; `{"incidentId", "readings": [...]}` |
| venomType vocabulary | uppercase `NEUROTOXIC | HEMOTOXIC | DRY_BITE | UNKNOWN` (review MEDIUM alignment — the reference's lowercase `dry_bite`/`neurotoxic` is superseded; `estimate_antivenom_vials` must not branch on an unreachable lowercase string) |
| Reading severity | lowercase `none | mild | moderate | severe` (matches Pydantic pattern and reference TS type) |
| VenomScoreResult shape | flat: `venomType, overallSeverity, dryBiteProbability, estimatedAntivenomVials, confidenceLevel, clinicalBasis, disclaimer, criticalAlert, ventilatorRequired, ptosisReadingCount, woundReadingCount, minutesSinceBite` (reference doc Step 3; supersedes the PATTERNS.md synthesized `vials`-nested shape) |

Severity thresholds (domain): closure 0–20 → `none`, 20–40 → `mild`, 40–70 → `moderate`, >70 → `severe`. `ptosisDetected` = closure > 40. `asymmetric` = |right − left| > 0.2 × baseline.

## Threat Model

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API (`/api/venom-score/*`) | untrusted callers submit clinically consequential ptosis readings for guessed incident IDs |
| route→WebSocket channel | server-computed scores pushed to all subscribers of an incident channel |
| API→DB | numeric medical readings persisted (no images) |

### STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-02-01 | Spoofing | POST/GET `/api/venom-score/*` | high-in-principle / medium-demo | mitigate | `require_role_if_enforced("victim","hospital_admin","system_admin")` declared on all three endpoints (off-by-default via AUTH_ENFORCED per auth.py:115-130); when auth is on, arbitrary clients cannot inject readings for guessed incident IDs |
| T-08-02-02 | Tampering | WS broadcast payload | medium | mitigate | payload computed server-side only (domain functions on persisted rows), never client-supplied; event string is the literal "VENOM_SCORE_UPDATE"; broadcast via ws.broadcast awaited inside the async route (broadcast_sync reserved for the worker thread) |
| T-08-02-03 | Information Disclosure | PtosisReading medical data | medium | mitigate | numeric apertures only — no images (wound.py imageB64 NULL precedent); every score carries an advisory disclaimer and clinicalBasis, never a directive; no PII beyond the incident id |
| T-08-02-04 | DoS | invalid aperture floods | low | mitigate | Pydantic ge=0.0 le=1.0 bounds on all aperture fields → free 422s before any DB write |
| T-08-02-SC | Tampering | npm/pip/cargo installs | N/A | N/A | no package installs in this plan |
