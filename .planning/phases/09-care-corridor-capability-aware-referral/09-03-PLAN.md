# Plan 09-03: Referral Lifecycle, Hospital Acceptance & Realtime Outbox Events

## Objective

Build backend REST API endpoints, guarded SQL state transitions, transactional outbox persistence (`append_outbox_tx`), and WebSocket broadcasting for the Care Corridor referral lifecycle, as detailed in [docs/CARE_CORRIDOR_PLAN.md](file:///c:/Users/OM%20Prakash/Documents/Nagaraksha-/docs/CARE_CORRIDOR_PLAN.md#8-api--real-time-specifications) and refined by [09-REVIEWS.md](file:///c:/Users/OM%20Prakash/Documents/Nagaraksha-/.planning/phases/09-care-corridor-capability-aware-referral/09-REVIEWS.md).

## Tasks

### Task 1: Transactional Outbox Helper & Event Handlers (`backend/app/eventbus.py`)
- Add `append_outbox_tx(conn: sqlite3.Connection, event_type: str, aggregate_id: str, payload: dict)` to write `OutboxEvent` using the caller's active connection and transaction.
- In `_process_event()`, add handlers for `ReferralCreated`, `ReferralAccepted`, `ReferralDeclined`, `TransportStarted`, `PatientArrived` to broadcast via WebSocket and log to `AuditEvent`.

### Task 2: Referral Route Module (`backend/app/routes/referrals.py`)
- Create `backend/app/routes/referrals.py`:
  - `POST /api/incidents/{inc_id}/evaluate-referral`:
    - Loads incident, presenting facility, latest VenomScore / Ptosis / Wound observations.
    - Calls `evaluate_capability_gap` and `rank_capable_hospitals`.
    - Returns `{ capabilityGap, recommendedHospital, eligibleHospitals, currentHospital }`.
  - `POST /api/incidents/{inc_id}/referrals`:
    - Atomically inserts `Referral` in `PENDING` state and `OutboxEvent('ReferralCreated')` via `append_outbox_tx()`.
    - Returns `ReferralResponse`.
  - `PATCH /api/referrals/{ref_id}/accept`:
    - Guarded transition: `UPDATE Referral SET status='ACCEPTED', acceptedAt=?, acceptedBy=?, updatedAt=? WHERE id=? AND status='PENDING'`.
    - If `cursor.rowcount == 0`, raises `HTTPException(409, "Referral is not pending or already resolved")`.
    - Enqueues `OutboxEvent('ReferralAccepted')`.
  - `PATCH /api/referrals/{ref_id}/decline`:
    - Guarded transition: `UPDATE Referral SET status='DECLINED', declinedAt=?, declinedReason=?, updatedAt=? WHERE id=? AND status='PENDING'`.
    - If `cursor.rowcount == 0`, raises `HTTPException(409, detail="Referral is not pending")`.
    - Enqueues `OutboxEvent('ReferralDeclined')`.
  - `PATCH /api/referrals/{ref_id}/transport`:
    - Guarded transition: `UPDATE Referral SET status='IN_TRANSIT', transportStartedAt=?, updatedAt=? WHERE id=? AND status='ACCEPTED'`.
    - If `cursor.rowcount == 0`, raises `HTTPException(409, detail="Referral must be accepted before transport")`.
    - Enqueues `OutboxEvent('TransportStarted')`.
  - `PATCH /api/referrals/{ref_id}/arrive`:
    - Guarded transition: `UPDATE Referral SET status='ARRIVED', arrivedAt=?, updatedAt=? WHERE id=? AND status='IN_TRANSIT'`.
    - If `cursor.rowcount == 0`, raises `HTTPException(409, detail="Referral must be in transit before arrival")`.
    - Enqueues `OutboxEvent('PatientArrived')`.
  - `GET /api/incidents/{inc_id}/corridor`:
    - Aggregates chronological 8-stage timeline: (1) Incident SOS, (2) Presenting Facility, (3) Telemetry & Observations, (4) Capability Gap, (5) Referral Target, (6) Hospital Acceptance, (7) Ambulance Transit, (8) Final Handoff / Arrival.

### Task 3: Router Registration (`backend/app/main.py`)
- Import `referrals.router` and register with `app.include_router(referrals.router)`.

### Task 4: Integration Tests (`backend/tests/test_routes.py`)
- Add `TestReferralLifecycle`:
  - Test evaluate-referral endpoint returns correct gaps and ranked capable hospitals.
  - Test create referral -> accept -> transport -> arrive sequence in order.
  - Test 409 Conflict on invalid state jumps (e.g. double accept, transport before accept).
  - Test `GET /api/incidents/{id}/corridor` complete timeline format and timestamps.
