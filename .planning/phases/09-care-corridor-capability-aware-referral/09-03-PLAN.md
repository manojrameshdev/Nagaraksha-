# Plan 09-03: Referral Lifecycle, Hospital Acceptance & Realtime Outbox Events

## Objective

Build the backend REST API endpoints, transactional outbox events, and WebSocket broadcasting channels for the complete Care Corridor referral lifecycle, as detailed in [docs/CARE_CORRIDOR_PLAN.md](file:///c:/Users/OM%20Prakash/Documents/Nagaraksha-/docs/CARE_CORRIDOR_PLAN.md#8-api--real-time-specifications).

## Tasks

### Task 1: Referral Route Module (`backend/app/routes/referrals.py`)
- Create `backend/app/routes/referrals.py`:
  - `POST /api/incidents/{id}/evaluate-referral`: reads incident, current facility, observations, calls domain evaluator, and returns gap + ranked targets.
  - `POST /api/incidents/{id}/referrals`: creates a new `Referral` record in `PENDING` state, emits `REFERRAL_CREATED` via `broadcast()`.
  - `PATCH /api/referrals/{id}/accept`: updates to `ACCEPTED`, sets `acceptedAt`, broadcasts `REFERRAL_ACCEPTED`.
  - `PATCH /api/referrals/{id}/decline`: updates to `DECLINED`, sets `declinedReason`, broadcasts `REFERRAL_DECLINED`.
  - `PATCH /api/referrals/{id}/transport`: updates to `IN_TRANSIT`, sets `transportStartedAt`, broadcasts `TRANSPORT_STARTED`.
  - `PATCH /api/referrals/{id}/arrive`: updates to `ARRIVED`, sets `arrivedAt`, broadcasts `PATIENT_ARRIVED`.
  - `GET /api/incidents/{id}/corridor`: returns unified chronological Care Corridor timeline.

### Task 2: Router Registration & Outbox Integration (`backend/app/main.py` & `eventbus.py`)
- In `backend/app/main.py`, import and register `referrals.router`.
- In `backend/app/eventbus.py`, handle `ReferralCreated` and `ReferralAccepted` in outbox event dispatcher.

### Task 3: Integration Tests (`backend/tests/test_routes.py`)
- Add `TestReferralLifecycle`:
  - Test evaluate-referral endpoint returns correct gaps and ranked DH hospitals.
  - Test create referral -> accept -> transport -> arrive sequence.
  - Test decline referral triggers re-route.
  - Test `GET /api/incidents/{id}/corridor` timeline shape and timestamps.

## Verification
