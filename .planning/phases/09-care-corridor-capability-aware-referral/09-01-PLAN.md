# Plan 09-01: Facility Capability Model & SQLite Schema Migration

## Objective

Extend the SQLite database schema and Pydantic models to store facility capability tiers (`PHC`, `CHC`, `SDH`, `DH`, `TERTIARY`), canonical capability tags (`ASV`, `OXYGEN`, `VENTILATION`, `ICU`, `BLOOD_BANK`, `DIALYSIS`, `EMERGENCY_CARE`), incident presenting facility linkage (`presentingHospitalId`), and the `Referral` lifecycle entity with SQLite `CHECK` constraints, as specified in [docs/CARE_CORRIDOR_PLAN.md](file:///c:/Users/OM%20Prakash/Documents/Nagaraksha-/docs/CARE_CORRIDOR_PLAN.md#7-database-schema-extensions-backendappdatabasepy) and refined by cross-AI review findings in [09-REVIEWS.md](file:///c:/Users/OM%20Prakash/Documents/Nagaraksha-/.planning/phases/09-care-corridor-capability-aware-referral/09-REVIEWS.md).

## Tasks

### Task 1: Extend SQLite Schema & Migrations (`backend/app/database.py`)
- In `SCHEMA`:
  - Add to `Hospital`: `facilityLevel TEXT DEFAULT 'PHC'`, `capabilities TEXT DEFAULT '["ASV","EMERGENCY_CARE"]'`, `ventilatorCount INTEGER DEFAULT 0`, `icuBedsAvailable INTEGER DEFAULT 0`.
  - Add to `Incident`: `presentingHospitalId TEXT REFERENCES Hospital(id)`.
  - Add `Referral` table:
    ```sql
    CREATE TABLE IF NOT EXISTS Referral (
        id TEXT PRIMARY KEY,
        incidentId TEXT NOT NULL,
        fromHospitalId TEXT NOT NULL,
        toHospitalId TEXT NOT NULL,
        status TEXT NOT NULL DEFAULT 'PENDING' CHECK (status IN ('PENDING', 'ACCEPTED', 'DECLINED', 'IN_TRANSIT', 'ARRIVED', 'COMPLETED')),
        urgency TEXT NOT NULL DEFAULT 'HIGH' CHECK (urgency IN ('CRITICAL_IMMEDIATE', 'HIGH_PRIORITY', 'ROUTINE')),
        missingCapabilities TEXT NOT NULL,
        clinicalReason TEXT NOT NULL,
        acceptedAt TEXT,
        acceptedBy TEXT,
        declinedAt TEXT,
        declinedReason TEXT,
        transportStartedAt TEXT,
        arrivedAt TEXT,
        createdAt TEXT NOT NULL,
        updatedAt TEXT NOT NULL,
        FOREIGN KEY (incidentId) REFERENCES Incident(id) ON DELETE CASCADE,
        FOREIGN KEY (fromHospitalId) REFERENCES Hospital(id),
        FOREIGN KEY (toHospitalId) REFERENCES Hospital(id)
    );
    CREATE INDEX IF NOT EXISTS idx_referral_incident ON Referral(incidentId);
    CREATE INDEX IF NOT EXISTS idx_referral_to_hosp ON Referral(toHospitalId, status);
    ```
- In `migrate_db()`:
  - Add safe `_column_exists()` checks and `ALTER TABLE Hospital ADD COLUMN ...` for the 4 hospital columns.
  - Add safe `_column_exists()` check and `ALTER TABLE Incident ADD COLUMN presentingHospitalId TEXT` for the incident column.

### Task 2: Pydantic Data Models (`backend/app/models.py`)
- Define `FacilityCapability = Literal["ASV", "OXYGEN", "VENTILATION", "ICU", "BLOOD_BANK", "DIALYSIS", "EMERGENCY_CARE"]`.
- Define `FacilityLevel = Literal["PHC", "CHC", "SDH", "DH", "TERTIARY"]`.
- Add `HospitalCapabilityUpdate(BaseModel)` with validated capabilities list and counts.
- Add `ReferralCreateRequest(BaseModel)` with `fromHospitalId`, `toHospitalId`, `missingCapabilities: list[FacilityCapability]`, `clinicalReason: str`, `urgency: Literal["CRITICAL_IMMEDIATE", "HIGH_PRIORITY", "ROUTINE"]`.
- Add `ReferralAcceptRequest(BaseModel)` with `acceptedBy: str`, `notes: str | None = None`.
- Add `ReferralDeclineRequest(BaseModel)` with `declinedBy: str`, `reason: str`.
- Add `ReferralResponse(BaseModel)` returning complete referral status and timestamps.

- Update `conftest.py` fixtures to support hospital capabilities, presenting facility IDs, and referral rows.
- Add unit tests in `backend/tests/test_domain.py` verifying `migrate_db()` idempotency, table creation, and foreign key enforcement.
