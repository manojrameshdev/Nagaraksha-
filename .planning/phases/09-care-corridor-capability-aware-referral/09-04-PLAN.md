# Plan 09-04: Care Corridor Frontend UI & Closed-Loop Timeline Component

## Objective

Build frontend UI components, Zustand store extensions, discriminated WebSocket event handlers, and typed API clients for the Care Corridor closed-loop referral timeline and receiving hospital console, as specified in [docs/CARE_CORRIDOR_PLAN.md](file:///c:/Users/OM%20Prakash/Documents/Nagaraksha-/docs/CARE_CORRIDOR_PLAN.md#9-care-corridor-ui-design-frontend) and refined by [09-REVIEWS.md](file:///c:/Users/OM%20Prakash/Documents/Nagaraksha-/.planning/phases/09-care-corridor-capability-aware-referral/09-REVIEWS.md).

## Tasks

### Task 1: TypeScript Interfaces & API Client (`frontend/lib/nagraksha.ts` & `realtime.ts`)
- In `nagraksha.ts`, declare:
  - `FacilityCapability = 'ASV' | 'OXYGEN' | 'VENTILATION' | 'ICU' | 'BLOOD_BANK' | 'DIALYSIS' | 'EMERGENCY_CARE'`
  - `FacilityLevel = 'PHC' | 'CHC' | 'SDH' | 'DH' | 'TERTIARY'`
  - `CapabilityGapEvaluation`, `Referral`, `CareCorridorTimeline`, `CorridorStage`
  - API helper functions: `evaluateReferral(incidentId)`, `createReferral(incidentId, data)`, `acceptReferral(referralId, data)`, `declineReferral(referralId, data)`, `startTransport(referralId)`, `confirmArrival(referralId)`, `getCorridorTimeline(incidentId)`.
- In `realtime.ts`, extend `IncidentSocketEvent` union with discriminated payloads:
  - `REFERRAL_CREATED`, `REFERRAL_ACCEPTED`, `REFERRAL_DECLINED`, `TRANSPORT_STARTED`, `PATIENT_ARRIVED`.

### Task 2: Zustand Store Integration (`frontend/store/sos-store.ts`)
- Add `activeReferral: Referral | null` and `corridorTimeline: CareCorridorTimeline | null` to `SosState`.
- Add `fetchCorridorTimeline: (incidentId: string) => Promise<void>` to load and reconcile complete timeline.
- In `updateFromWsEvent`: when receiving any referral event, update `activeReferral` immediately and trigger `fetchCorridorTimeline(incidentId)` for full reconciliation.

### Task 3: Care Corridor Timeline Component (`frontend/components/care-corridor-timeline.tsx`)
- Build `CareCorridorTimeline`:
  - Renders the 8 vertical steps with icons and color-coded status badges:
    1. Incident Reported (Time, Coordinates)
    2. Presenting Facility (e.g. *Malavalli Taluk PHC*)
    3. Clinical Telemetry (VenomScore: 50% Ptosis, MODERATE neurotoxic)
    4. Capability Gap Detected (?? *Mechanical Ventilation Unavailable at PHC*)
    5. Capable Referral Target (e.g. *Mandya District Hospital*, 4 Vents, 42 ASV Vials)
    6. Receiving Facility Acceptance (? *Accepted by Mandya DH — Ventilator Reserved*)
    7. 108 ALS Ambulance Transit (?? *In Transit — ETA 18 min*)
    8. Patient Arrived & Handoff (?? *Arrived at Mandya DH — Care Completed*)
  - Interactive Action Panel for Receiving Hospital (`?role=hospital`):
    - One-tap **ACCEPT & RESERVE VENTILATOR** button.
    - **RE-ROUTE** button.
    - Error banners and loading spinners during mutation.

### Task 4: Incident Page Integration & Tests (`frontend/app/incidents/[id]/page.tsx`)
- Mount `CareCorridorTimeline` on `/incidents/[id]` page.
- Add MSW handlers in `frontend/test/handlers.ts` for all referral endpoints and corridor timeline.
- Create `frontend/components/__tests__/care-corridor-timeline.test.tsx` verifying:
  - Correct rendering of all 8 corridor stages.
  - Capability gap warning display.
  - Acceptance action click and optimistic store update.
