  <action>
    1. Run ESLint to see all violations:
       ```bash
       cd frontend
       bun run lint 2>&1
       ```

    2. For each violation of `prefer-const`, `no-unused-vars`, `no-console`, or `eslint-plugin-security` rules:

       **prefer-const violations:** Change `let` to `const` for variables that are never reassigned. Only change the declaration keyword — do NOT change variable names or logic.

       **no-unused-vars violations:** Either:
       - Remove the unused variable declaration, OR
       - Prefix with underscore (`_unusedVar`) if the variable is intentionally unused as a placeholder/destructuring target

       **no-console violations:** Either:
       - Remove the `console.log()` statement if it's leftover debugging code, OR
       - Add `// eslint-disable-next-line no-console` comment above intentional logging (e.g., in dev scripts, error handlers where console output is the intended behavior)

       **eslint-plugin-security violations:** Either:
       - Fix the insecure pattern (e.g., replace `eval()` with safer alternative), OR
       - Add inline `// eslint-disable-next-line` comment with a reason if the pattern is safe in context (e.g., ReDoS in test fixtures)

    3. After fixing, re-run ESLint to verify:
       ```bash
       cd frontend
       bun run lint 2>&1
       ```
       The goal is zero errors and zero warnings for the enabled rules. If zero is not achievable (e.g., too many violations), at minimum zero errors and document remaining warnings.

    4. Keep a record of any inline eslint-disable comments added with the rationale.
  </action>
