<objective>
Set up Bandit Python security scanner with configuration, install the dependency, and resolve any high-severity findings in the backend codebase.

**Purpose:** Catch Python security vulnerabilities (command injection, SQL injection, hardcoded secrets, unsafe file operations, shell injection) automatically during development. Bandit complements eslint-plugin-security (frontend) with Python-specific coverage.

**Output:** Bandit installed in backend dependencies, `.bandit.yaml` config created, high-severity findings fixed or suppressed with documented rationale, scan passes cleanly.
</objective>

<task type="auto">
  <name>Task 2: Scan backend code and fix high-severity findings</name>
  <files>backend/app/**/*.py, .bandit.yaml (if config tuning needed)</files>
  <read_first>
    - `.bandit.yaml` (config — scan parameters)
    - `backend/app/` directory listing (scope of scan)
  </read_first>
  <action>
    1. Run the initial Bandit scan:
       ```bash
       bandit -r backend/ -c .bandit.yaml -f json 2>&1
       ```

    2. Parse the JSON output for high-severity, high-confidence findings. For each finding:
       
       **Fix the root cause** where possible:
       - Hardcoded SQL strings: Move to parameterized queries (Bandit B608)
       - Hardcoded passwords/keys: Move to environment variables
       - Use of `eval()`/`exec()`: Refactor to safer alternative
       - Shell injection risks: Use `subprocess.run` without `shell=True`
       
       **Add inline `# nosec` comments** ONLY when the finding is a false positive and the code is demonstrably safe:
       - Always add a comment on the line above explaining why it's safe
       - Format: `# nosec — <reason>`
       - Example:
         ```python
         # nosec — B311: random used for non-security simulation data, not cryptography
         mock_value = random.randint(1, 100)
         ```

    3. Verify bandit config excludes correctly:
       - `exclude_dirs` properly skips frontend, node_modules, .git
       - Bandit should NOT scan `.planning/` or `docs/`

    4. Re-run after fixes:
       ```bash
       bandit -r backend/ -c .bandit.yaml 2>&1
       ```
       
    5. Target: Zero high-severity findings (CONFIDENCE_HIGH + SEVERITY_HIGH).
       Medium/low findings are acceptable and managed by the severity threshold in `.bandit.yaml`.

    Only add `# nosec` comments as a last resort after attempting real fixes. Every `# nosec` must have an accompanying explanation comment.
  </action>
